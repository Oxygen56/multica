# STRAT-007: 第三方服务依赖风险评估 — 答案（Group A 基线）

## 风险评估矩阵

### 风险维度说明

评估基于五个维度：
- **可替代性**：有无等价替代方案，迁移成本
- **供应商锁定**：API/数据格式的专有程度
- **定价稳定性**：历史价格变化频率和幅度
- **故障影响面**：服务不可用时的用户影响范围
- **合规风险**：数据隐私和地域合规要求

---

### Auth0（认证）— 风险等级：中

**分析**：认证是产品的安全基石，任何故障都将完全阻断用户访问。Auth0基于标准协议（OAuth2.0/OIDC/SAML），用户身份数据可导出。

**缓解策略**：
- 保持用户身份数据的定期导出备份
- 应用层缓存JWT公钥（JWKS），Auth0短暂不可用时已登录用户不受影响
- 维护可切换的备用认证提供者配置（如直接使用云厂商的OAuth服务）

**Fallback方案（Auth0长时间不可用）**：
- 切换至云厂商原生方案（如AWS Cognito/Azure AD B2C），利用预先导出的用户数据
- 预计切换时间：4-8小时。**但需要用户重置密码**（密码哈希不可迁移）

---

### Stripe（支付）— 风险等级：高 ⚠️

**分析**：支付是收入命脉。Stripe的API是专有的（非标准化），且支付数据的PCI合规处理高度依赖Stripe。迁移成本极高。

**缓解策略**：
- **双重支付渠道**：同时集成至少一个备用支付网关（如Adyen/PayPal），降低单点依赖
- **支付数据本地缓存**：在PCI合规范围内，保存交易记录摘要
- **异步处理**：支付结果通过Webhook异步确认 + 主动轮询双保险

**Fallback方案（Stripe故障>1小时）**：
- 启用备用支付网关，前端动态切换支付方式
- B2B客户可切换到手动发票模式（短期方案）
- **预计切换时间**：30分钟（预先集成的前提下）
- **不可迁移项**：已保存的信用卡token（Stripe专有），用户需重新输入

---

### SendGrid（邮件）— 风险等级：低

**分析**：邮件是异步通信（非实时），短暂延迟用户无感知。SMTP是开放标准，切换成本低。

**缓解策略**：
- 配置至少2个SMTP服务提供商（如SendGrid主 + AWS SES备用）
- 应用层实现邮件队列（Redis/MQ），确保发送失败不丢失
- 关键事务邮件（密码重置、订单确认）SLA监控

**Fallback方案**：切换DNS的MX/SPF记录到备用提供商，应用层切换SMTP配置。切换时间<15分钟，零数据丢失。

---

### Mapbox（地图）— 风险等级：中

**分析**：地图功能在部分产品中是核心体验（如物流追踪、位置选择），但不是所有用户都高频使用。Mapbox基于MapLibre GL JS（开源的Mapbox GL分支），API有一定程度的标准化。

**缓解策略**：
- 使用MapLibre GL JS（与Mapbox API兼容的开源渲染引擎）作为前端SDK
- 瓦片数据使用OpenStreetMap作为后备数据源
- 地理编码（Geocoding）功能可用Nominatim（OSM）或云厂商服务替代

**Fallback方案**：
- 切换瓦片服务到自托管（基于OpenMapTiles + 自建瓦片服务器）或切换到MapTiler Cloud
- **预计切换时间**：瓦片服务24小时（需预处理），Geocoding即时切换
- 降级方案：地图功能临时禁用，仅保留地址文本输入

---

### AWS S3（存储）— 风险等级：中

**分析**：S3是AWS最稳定的服务之一，历史可用性>99.99%。但对象存储API已高度标准化（S3 API成为行业标准），迁移可行。

**缓解策略**：
- 使用S3-compatible SDK（MinIO SDK/boto3），允许无缝切换至其他S3-compatible存储
- 关键数据跨区域复制（Cross-Region Replication）
- CDN层（CloudFront/Cloudflare）缓存静态资源，S3短暂不可用时CDN兜底

**Fallback方案**：
- 切换到Cloudflare R2（S3-compatible，零出口费）或自建MinIO集群
- **预计切换时间**：DNS变更10分钟 + 数据增量同步（取决于数据量）
- 挑战：存量100TB数据的迁移可能需要数周

---

### GitHub API（代码集成）— 风险等级：低

**分析**：代码集成通常是辅助功能（如查看PR状态、触发CI），非核心业务路径。GitHub API生态成熟。

**缓解策略**：
- 支持GitLab/Bitbucket API作为多源选择（或一开始就做多源适配）
- API响应缓存（仓库元数据变化频率低）
- 优雅降级：GitHub不可用时，相关功能灰色不可用而非报错

**Fallback方案**：无需紧急fallback——GitHub的可用性极高（状态页数据显示年可用性>99.9%），且故障影响非核心功能。如需要，切换至GitLab API（需提前适配）。

## 风险汇总

| 服务 | 风险等级 | 核心风险 | 切换时间 | 数据迁移难度 |
|------|---------|---------|---------|-------------|
| Stripe | **高** | 专有API，支付数据锁定 | 30min+重输卡 | 高 |
| Auth0 | **中** | 认证阻断 | 4-8h+密码重置 | 中 |
| Mapbox | **中** | 瓦片服务锁定 | 24h（瓦片） | 中 |
| AWS S3 | **中** | 数据量大 | 10min（DNS）| 高（存量） |
| SendGrid | **低** | 几乎无 | <15min | 低 |
| GitHub API | **低** | 非核心功能 | 即时切换 | 低 |
